# Estimate-Only Image Benchmark

**Date:** 2026-07-31<br>
**Image:** `toti330/dsp_seed_finder:0.8.0-estimate-only`<br>
**Digest:** `sha256:ac619c981d6df387b02d8928d741a1db906f7e22e31a6a9e43be0519344a4792`<br>
**Source base:** `0df70ce645d4573ea135ea179a1261890851ec00`

This image keeps the historical fast midpoint estimator (`use_actual_veins=false`).
It stores one `estimate_*` value for each ore and omits the `min_*` and `max_*`
columns. The writer also waits through normal input lulls rather than panicking.

## Results

| Mode | Seeds | Workers | Writers | Throughput |
| --- | ---: | ---: | ---: | ---: |
| Generation only | 10,000 | 2 | 1 sink | 246.741488 seeds/s |
| PostgreSQL write | 10,000 | 2 | 1 | 178.220602 seeds/s |
| PostgreSQL write | 10,000 | 2 | 2 | 178.659582 seeds/s |

The test host had two logical processors, 7.7 GiB of memory, Docker 29.6.1,
and an `x86_64-unknown-linux-musl` executable. Logs, checkpoints, and the TUI
were disabled. Adding a second database writer did not materially improve
throughput.

## Storage

The 10,000-seed PostgreSQL sample inserted 640,000 stars and 2,441,744 planets.
The two table-and-index relation sizes totalled 439,885,824 bytes, or about
43,989 bytes per seed.

The raw machine-readable record is
[`2026-07-31-0.8.0-estimate-only.json`](2026-07-31-0.8.0-estimate-only.json).

## Provenance

The benchmark ran against the local estimate-only build immediately before the
release metadata was added. The published image has the same sole RootFS layer,
`sha256:a02019e60bdde18a35b97d8109579b5ec03aed53a517c3a92848147f4a108aa9`,
so it executes the identical binary.
